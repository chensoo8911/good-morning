今日一學

知識點：Empty State（空狀態）

說明：當畫面上沒有任何資料可以顯示時的狀態（例如：剛註冊還沒有好友、購物車是空的、搜尋不到結果），就稱為 Empty State。

平面設計師剛轉 UI 時常犯的錯：只放一行字「目前沒有資料」。

怎麼做才好（步驟拆解）：

1. 告知現狀：用輕鬆易懂的文字與插圖，告訴使用者現在發生了什麼事（例：「您的購物車空空的」）。

2. 提供指引：給予明確的下一步動作按鈕（Call to Action, CTA），引導使用者去填補這個空缺（例：放一個「去逛逛」的大按鈕）。

3. 消除挫折感：如果是錯誤或搜尋不到造成的空狀態，可以提供替代方案或熱門推薦，避免使用者直接離開。

Call to Action (CTA / 行動呼籲)：

在 UI 設計中，CTA 就是那個「你最希望使用者點擊的按鈕」，例如購物網站的「加入購物車」或註冊頁面的「立即註冊」。為了讓它最顯眼，我們通常會給它最強烈的顏色（主色）並放在畫面上容易注意到的地方。設計師在排版時，永遠要先想清楚「這個畫面最重要的 CTA 是哪一個？」

最繁重的任務（如洞察報告、多 subagent 掃描）常在執行途中因觸及上限而終止，且未能將結果寫入硬碟，導致心血白費。

範圍蔓延與意圖誤解

發生了至少 14 次需中斷 Claude 執行的情況。原因包含 Claude 過度擴展任務範圍（如要求處理單一圖層卻連 git 也一併檢查），或將單純的提問誤認為技能觸發（如問「我是誰」卻觸發了 whoami 技能）。

初版腳本與自動化步驟常需重工

包含錯誤的程式碼佔了最大摩擦來源（26 次）。特別是在 Shell script、檔案同步自動化方面，常出現 Zsh word-splitting、CJK 檔名解析脆弱或 FTP 550 錯誤，通常需要事後進行驗證才能抓出問題。

可以試試的功能

增量儲存結果防中斷

在派發 subagent 的研究任務時，要求「先建立檔案並即時寫入結果」，避免耗盡額度時一無所獲。

將大量 Bash 操作轉為腳本

本週使用了 1849 次 Bash，很多是重複的資料夾比對。應該把這些邏輯提取並寫成穩定的腳本，並確保正確處理 CJK 檔名等邊界狀況。

擴展 Hooks 與自訂技能

建議在每次寫入或編輯時使用 PostToolUse hook 自動執行 PII（機密資料）掃描；並將重複的 5 步發布流程打包為自訂的 /release 技能。

預設加入對抗性驗證 (Self-verify loop)

在要求寫腳本的當下，直接規定派發一個「沒有先前上下文」的獨立 verifier agent 來測試極端邊界狀況，不要等事後才驗證。

無頭模式 (Headless Mode)

讓排程的爬蟲與研究任務在無頭模式下執行，避免受限於互動模式的 session 限制，也更易於從中斷點重啟。
